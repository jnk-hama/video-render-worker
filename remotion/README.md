## なぜ作ったか

ffmpeg版は「素材を切って並べて字幕を焼く」ことはできますが、
**背景と前景を同じカメラで動かす**のは苦手です。`zoompan` は1本の映像に
対する拡大で、複数のレイヤーを1つのカメラで連動させる概念がありません。

「製品がその空間に実際にある」ように見せるには、背景と製品が
**違う量だけ**動く必要があります（視差）。これはレイヤーとカメラを
分けて持てる仕組み — つまりReact（Remotion）の方が素直に書けます。

参考にした実装：
- [video-talkcraft](https://github.com/Vincentwei1021/video-talkcraft) — 口播（解説）動画。語尾同期字幕とカメラ体系
- [video-shotcraft](https://github.com/Vincentwei1021/video-shotcraft) — 製品PR動画。運鏡・リズム・SE

## 構成

```
remotion/
├─ package.json          依存（remotion / react のみ。余計なものを入れない）
├─ remotion.config.ts    画質と描画時間の設定
├─ scripts/render.mjs    Actions から呼ぶ入口。★描画秒数を必ず出す
└─ src/
   ├─ index.ts           registerRoot
   ├─ Root.tsx           Composition。寸法と尺は台本から決める
   ├─ Video.tsx          シーンの振り分け（ルーティング）
   ├─ types.ts           台本の形。ffmpeg版と同じ語彙を使う
   ├─ lib/camera.ts      ★運鏡。1つのカメラ値から全レイヤーを導く
   ├─ scenes/
   │  ├─ InSitu.tsx      ★中核。背景動画＋透過製品＋視差
   │  ├─ Shot.tsx        製品デモ（2.5Dで傾けて見せる）
   │  └─ Talk.tsx        口播（語り手＋見出し）
   └─ components/
      ├─ Captions.tsx    字幕。強調語だけ色を変える
      └─ Disclosure.tsx  広告表記。全編に出す
```

## 「貼り付けた感」を消す4つの手がかり

`src/scenes/InSitu.tsx` はこの4つを全部潰しています。1つでも欠けると
「合成しました」という絵になります。

| # | 症状 | 対処 |
|---|---|---|
| 1 | 書き割りに見える | **視差**。1つのカメラ値から depth 違いで背景(0.85)と製品(1.25)を導く |
| 2 | 宙に浮く | **接地影**。製品の真下に楕円の影。寄るほど濃く小さくなる |
| 3 | 照明が合わない | **環境光**。背景の色を製品の形（アルファ）で切り抜いて薄く乗せる |
| 4 | 動きが硬い | **手持ちの微振動**＋spring の立ち上がり。背景と製品で位相をずらす |

★4のノイズに `Math.random` を使わないこと。Remotion はフレームを並列に
描くので、同じフレームが常に同じ値にならないと**チラつきます**。
周期の違う正弦波を足して作っています（`lib/camera.ts` の `handheld`）。

## 使い方

```bash
cd remotion
npm ci
npm run studio                              # ブラウザで確認しながら作る
node scripts/render.mjs --payload payload.json --out out.mp4
```

`payload.json` は `{"job": {...}}` でも素の台本でも受けます
（ffmpeg版と同じ）。形は `src/types.ts`、例は `src/sample-script.json`。

## 描画時間（実測）

**測りました。無料枠に収まります。**

同じ素材で尺だけ変えて2回描き、固定費と可変費を分けました
（4コアの環境。1080x1920@30fps）。

| 尺 | 描画にかかった時間 |
|---|---|
| 3.0秒 | 27.2秒 |
| 12.0秒 | 88.0秒 |

→ **固定費 6.9秒（束ね＋Chrome起動）＋ 動画1秒あたり 6.76秒**

| 本数 | 13秒の動画1本 | 月あたり | 無料枠2,000分 |
|---|---|---|---|
| 16本/日 | 95秒（1.6分） | 758分 | 収まる |
| 23本/日 | 95秒（1.6分） | 1,090分 | 収まる |

ffmpeg版は1本 **67秒**（実測）なので、**1.4倍ほど遅くなる**代わりに
視差・接地影・環境光が手に入る、という交換になります。

**★この数字は4コアの環境での実測です。GitHub の無料ランナーは2コアなので、
  もっと遅くなる可能性があります。** `scripts/render.mjs` は毎回
「動画1秒あたり何秒かかったか」を出すので、Actions での初回にこの値を
取り直してください。倍の 13.5秒/秒 でも 23本/日で約2,180分となり、
**16本/日なら収まりますが23本/日では超えます**。

超過した場合の手は、この順で効きます。
1. `node_modules` と Chrome Headless Shell を Actions のキャッシュに載せる（毎回の準備時間を削る）
2. `Config.setJpegQuality` を下げる
3. **Remotion で描くのは `insitu` / `shot` シーンだけにし、残りは ffmpeg 版で描く**
   （語りだけのシーンにChromeを使う理由が無い）

## まだ出来ていないこと（実測で分かった残り3件）

初回の描画で**実際に確認した**未完成点です。「動いた」とは言えますが
「仕上がった」とは言えません。

| # | 症状 | 原因 | 直し方 |
|---|---|---|---|
| 1 | 日本語フォントが別物になる | Dela Gothic One を読み込んでいない。Chromeの既定フォントへ落ちた | `@remotion/google-fonts` で読むか、`assets/ja/fonts` を `@font-face` で登録する |
| 2 | 字幕の黒縁が細い | `-webkit-text-stroke` は libass の縁取りほど太くならない | 縁は別レイヤーの複製で作る（8方向へずらした影を重ねる） |
| 3 | 環境光（ambient）が効いていない | CSSマスクの画像取得が `ERR_FAILED` になった（クロスオリジン） | 製品画像を一度ローカルへ落としてから読む。描画側で取得する形へ変える |

★1と2を直すまでは、**ffmpeg版の方が字幕は読みやすい**。
  ミュート再生で読めない字幕は無いのと同じなので、ここは譲れない。

## 本番へ接続する前に決めること

このディレクトリは**まだどこからも呼ばれていません**。
`.github/workflows/render-video.yml` は従来どおり ffmpeg 版を呼びます。

接続するなら、依頼側（`process-job`）が
`"renderer": "remotion"` のような1項目を足し、ワークフローが
それを見て呼び分ける形が最小の変更です。両方を残しておけば、
Remotion側が壊れた日に ffmpeg 版へ戻せます。
