# 同梱素材の置き場所（部門で分ける）

★★2026-09-04、決定#082。**注意ではなく構造で分ける。**

```
assets/
  shared/   両部門で使う      bgm/ sfx/ demo/ neutral-gradient.mp4
  en/       Aライン専用       fonts/(Anton) clips/(b-*.mp4) influencer/(anna)
  ja/       Bライン専用       fonts/(Dela Gothic One)
```

## 守られ方（実測で確認済み）

依頼に `target_market: "ja" | "en"` を入れる。描画側は次のように振る舞う。

| 状況 | 挙動 |
|---|---|
| `ja` の依頼が `assets/en/…` を指した | **描かずに停止** |
| `en` の依頼が `assets/ja/…` を指した | **描かずに停止** |
| 本文が日本語なのに `target_market: "en"` | **描かずに停止** |
| 値が `ja` / `en` 以外 | **描かずに停止** |
| 未指定 | 本文の文字種から推定し、警告を出して続行（下記） |

★「使わずに次のクリップへ」ではなく**止める**。黙って別の映像に
  差し替わる方が危険で、出来上がった動画を見るまで誰も気づかない。

## 未指定をまだエラーにしていない理由

英語圏部門（GAS）は `clasp push` が済むまで古いコードのままで、
このフラグを送らない。ここで落とすと、描画側を更新した瞬間に
**Aラインが全部止まる**。デプロイの順番で壊れる設計は既に2度踏んでいる
（#076 のcron認証、#079 のYAMLパース）。

**切り替え条件**：GAS（`36_Render.js`）と Supabase（`handleWaitingRender`）の
**両方が送っていることを実走で確認できたら**、`resolve_market()` の
「指定なし」分岐を `SystemExit` に変える。

## 踏んだ失敗（消さずに残す）

決定#069でJSON2Videoを外した時、Pexelsが素材を返さなかった場合の
フォールバックを `assets/b-beach-sunset.mp4` にした。これは
**Aライン（英語圏・水着のモデル映像）** で、日本語の商品紹介動画に
出てくると内容と全く噛み合わない。TikTokの審査に出す動画でこれが
起きれば、内容の不一致として不利にもなる。

→ `shared/neutral-gradient.mp4` に変更し、さらに置き場所自体を分けた。

## neutral-gradient.mp4 の作り方

```bash
ffmpeg -y -f lavfi -i "gradients=s=1080x1920:c0=0x0b0b12:c1=0x1b1230:x0=200:y0=200:x1=900:y1=1700:d=12:speed=0.06,format=yuv420p" \
  -t 12 -r 30 -vf "noise=alls=6:allf=t+u,eq=brightness=-0.02" \
  -c:v libx264 -preset veryfast -crf 26 assets/shared/neutral-gradient.mp4
```

## 背景に合成のグラデーションを使わない（2026-09-11）

★★一度 `preview-motion.mp4`（紫の動くグラデーション）を「確認用」として
  置いたが、**削除した。**

  オーナー指摘「バックの紫のやつなに？おかしい！」。
  背景が暗いという指摘に対して合成のグラデーションを作って当てたが、
  商品紹介の動画で後ろが抽象的な紫では、**そもそも商品紹介に見えない。**
  「暗い」の反対は「明るい」ではなく「**その商品を使っている場面**」だった。

★確認用のつもりでも、置いてあると使ってしまう。だから消す。
  背景は**実写**（本番はPexels、確認時も実写）を使うこと。
  実写が用意できない時は、背景を作るのではなく**用意してから描く**。

## 背景に「別の同種商品」を映さない（2026-09-12・決定#132）

★★オーナー指摘「掃除機のアフィリエイトだとおもうが、途中で別の掃除機に
  変わってる」「取ってきた画像の掃除機そのものを使用してる動画を生成する事
  これは前提を崩さないように」。

【何が起きたか】
使用シーンをPexelsから引いた時、素材にそれぞれ**違う掃除機**が写っていた。
1本の動画の中で商品が5回変わって見え、**何を売っているのか分からない**。

【前提（崩さない）】
CLAUDE.md の C案にこう書いてある：

  > 生成物は「シチュエーション」に限る。商品そのものは必ずASPの実画像を出す。

つまり役割分担はこう：

  背景（Pexels）  … **状況だけ**。商品は写っていてはいけない
  前景（ASPの実画像）… **商品そのもの**。これが唯一の商品

【素材を選ぶ時の条件】
・売る商品と**同じ種類の物**が写っている素材は使わない
  （掃除機を売るなら、掃除機が写っている素材は背景にできない）
・状況は「困りごと」と「その後」で作る
  例）ペットの毛が付いたラグ／散らかった床／片付いた部屋・くつろぐ人
・検索語も「vacuuming（掃除機を使う）」ではなく
  「pet hair carpet」「messy floor」のように**状況**で引く

★これを守ると、画面に出る商品は合成した1つだけになり、
  最後まで同じ商品を見せられる。

効果音の作り方は `shared/sfx/README.md`。

## 生成した「使用シーン」は確認用（2026-09-12・決定#135）

`shared/demo/gen-robot-*.jpg` は **product-scene（Gemini画像生成）の
出来を確かめるために作った3枚**である。本番の素材ではない。

★★これらの画に写っている掃除機は、**モデルが描き直したもの**であって
  元の商品写真の画素そのものではない。元にした写真は Wikimedia Commons の
  iRobot Roomba（CC BY-SA 4.0）で、実在するブランドの製品が写っている。
  **別の商品のアフィリエイト動画にこのまま使ってはいけない。**

【本番での使い方】
1. ASPの実画像を product-scene へ渡す
2. 返ってきた画を **人（Nexus）が目視**し、商品が描き変わっていないかを見る
3. 通ったものだけを背景として使う

この2番を飛ばさないこと。飛ばすと「似た商品」を本物として見せることに
なり、優良誤認（景表法）に触れる（#068の法務制約）。

## 困りごとの場面は「その商品が解決するもの」に限る（2026-09-12・決定#137）

★★オーナー指摘「一枚目に埃まみれの服を出してますが、紹介している
  ロボット掃除機は通常服の埃を取りません、そんな使い方をしません」。

【何をやったか】
1枚目に**毛だらけのセーター**を出した。絵として毛の量が分かりやすかったから
選んだが、**ロボット掃除機は服の毛を取らない**。

【なぜ致命的か】
1〜2枚目の困りごとと、3枚目で出す商品が繋がらない。見ている人は
「別の商品の話をしている」と受け取る。**動画の筋が通らなくなる。**

【素材を選ぶ時に必ず自問する】
  **「その困りごと、この商品を買ったら本当に消えるか?」**
消えないなら使わない。絵として面白いという理由で選ばないこと。

差し替えた2枚（どちらもロボット掃除機が実際に解決する）:
  gen-problem-00 … コロコロを何枚も使って床の毛を取っている（終わらない）
  gen-problem-01 … ソファ下の毛に手が届かない（人の手では取れない）
